# 沙叶 GMP 质量中枢

[English](README.md) · [演示 / Demo](DEMO.md) · [领域说明 / Domain notes](DOMAIN-NOTES.md)

Agnes Harness（AGH）的药厂质量应用插件，包名 `@agnes-showcase/pharma-gmp`，版本 1.2.5。沙叶 / Sableleaf OSD、人员、产品、签名和证据均为虚构合成。本应用是非无菌片剂/胶囊质量系统的教学示例，未经计算机化系统验证，不可用于真实放行或申报。

## 做什么

36 个批次、240 条环境记录、9 台设备、12 个偏差，场景时点为 **2024-10-20**。工作台整合质量总览、待办与签署、实时对象档案，以及批记录、偏差/CAPA、EM、QA 放行和审计模块。质量助手是统一入口，委派偏差调查、批记录复核、环境监测和放行前检查四个角色，委派卡片与完成通知保留角色归属。

质量助手是统一入口：委派偏差调查、批记录复核、环境监测和放行前检查四个角色，汇总结论，并在主会话执行用户明确要求的签署登记、推进和放行。质量记录与放行需要绑定精确版本的人工业务签名。

## 安装

需要支持插件 API `^5.0.0` 的 AGH，Node >= 24.10。从 Git 安装（仓库已提交构建好的 `dist/`）：

```sh
agh plugins add git:https://github.com/AgnesAI-Labs/agh-app-pharma-gmp#v1.2.5
```

也可以打成 `.tgz` 再安装：

```sh
git clone --branch v1.2.5 https://github.com/AgnesAI-Labs/agh-app-pharma-gmp.git
agh plugins pack ./agh-app-pharma-gmp ./pharma-gmp-1.2.5.tgz
agh plugins add ./pharma-gmp-1.2.5.tgz
```

在插件页审阅准确的能力和完整性后信任、启用；在 **设置 → 应用** 预览并采纳沙叶应用。安装本身不采纳应用。选择 Demo 模型可通过 `call pharma_inspect {"batch":"B-2410-017"}` 等精确工具提示复现。推理步骤使用真实模型并参考 DEMO。`/?admin` 与 `agh app clear` 保留恢复能力。请勿将 home 指向真实 AGH 数据。

## 申请的能力

声明在 `package.json` 的 `agnes.plugins`，信任前 AGH 会展示供审阅。

| 插件入口 | 能力 |
|---|---|
| `main` | `ui`；`store`（owner/profile 存储）；`filesystem` 读写仅限 `pharma-output/**`；工具 `pharma_inspect`、`pharma_dossier`、`pharma_record`、`pharma_release`、`pharma_report`（前缀 `pharma_`）；`tools.invoke`。注入工具、服务、技能和 provider。 |
| `cards` | 仅 `ui`（证据卡片）。 |

运行时库（`@agnes/extension-api`、`@agnes/plugin-runtime`、`@sinclair/typebox`、`react`、Web UI 包）由宿主提供，不随包打入。

## 行为说明

所有页面通过声明的 `pharma.snapshot`、`pharma.change`、`pharma.release` 档案服务访问数据，无需活动会话。后端状态在宿主绑定的 owner/profile 存储中持久化；无浏览器数据库和私有文件路径。变更采用事务、单调版本和审计记录；原始 OOS 不覆盖。页面保留 operationId，待审批/未知回执先查询；不得盲目重新提交。QA 放行同时检查清单、精确版本、固定签名含义及宿主批准凭证，签名人来自批准凭证。

`pharma_report` 生成 Markdown 与可打印 HTML，并调用 `present`。夜间任务通过环境监测智能体的标准 `schedule_create` 创建。智能体成长通过宿主插件候选工具创建、测试、提交审阅，并由人工发布精确哈希。会话继续使用宿主的代码 pin；升级不改写旧记录。

角色 preset 通过公开 tool-policy SPI 选择包内策略，保留默认工具权限行为。质量写入与放行另行请求绑定精确参数及版本的单次业务签名；完全访问下由 Host 代表会话真人自动确认符合合同的签署，其他权限由人确认。缺少 Host 裁决凭证的领域写入仍拒绝。

仅精确的夜间 EM 导出（kind=em 加支持的语言）允许无人值守：只读取质量状态，并在 pharma-output/ 内创建新的报告文件。其他报告形状保留默认决策；质量记录与放行仍要求绑定的业务裁决，只有符合合同的完全访问主会话请求自动确认。

放行档案工具同时返回原始历史发现、当前阻断和偏差结案、复验、EM、设备追溯证据。证书绑定签署前被审阅的档案版本；签署使状态版本加一。

## 业务签名

质量记录与批次放行属于业务签署。工具以 `business.confirm` 绑定精确参数、对象、版本、证据及签名含义。完全访问下，宿主代表选择该权限的会话真人提交声明的批准值，不出现待审卡片；回执、审计及放行证书／关闭记录明确标注 **完全访问下自动确认**，不能冒充人工点击或模型签名。其他权限保留人工签署、拒绝、取消和过期语义。宿主单次消费原决策，私有凭证在存储事务内复核当前 epoch、取消及有效期，提交前收窄权限会阻止写入。批准合同缺失或歧义时仍请求人工。页面 effect 保留宿主人工确认与修订校验。

签署卡按当前界面语言展示业务对象、审阅版本、精确签名含义及证据链接；宿主答复必须返回该展示版本绑定的原文。回执和审计保存所见含义；仅返回旧式空答复不能完成新签署。

1.2.2 将报告生成声明为历史证据工具，Core 在调度前等待会话历史完整校验。

1.2.1 新增角色子代理与质量助手统一入口；已有安装可在插件页审阅捆绑更新。安装与应用采用仍分开进行。

工作台提供当前对象、待签署、证据与报告。通过对象按钮或输入区快捷操作开展偏差、CAPA、EM、批记录复核与 QA 放行；四个专家子代理在委派卡片和完成通知中显示归属。主导航只保留总览和待办与签署，其他模块从更多或总览链接进入。

1.2.1 以“质量助手”为统一入口：快捷操作和对象操作均进入主会话，由它委派偏差调查、批记录复核、EM 分析和放行前检查四个角色。角色使用配方中的持久人格启动全新会话，权限是启动时角色与父会话工具、文件、网络、沙箱及只读权限的交集。委派卡片和完成通知记录角色归属，刷新后仍可查看。需审批的工具调用在父会话人类卡和 Web 审批标签等待，只能由已认证的人单次允许或拒绝，无人类界面则拒绝；父会话或祖先停止、关闭会撤回待决请求。角色子代理不能业务签署，父会话完全访问也不例外；质量助手先汇总结果，再在主会话执行用户要求的签署登记、推进或放行。

质量助手等待角色调查结论，在一条用户消息内完成汇总，并在主会话执行用户明确要求的签署登记；生成的报告会附带路径说明。委派卡展示角色、任务和持久状态，提供“查看子任务”；内部编号收进“技术详情”。长任务仍可使用后台完成通知。


## 开发

```sh
npm run build        # 用 esbuild 0.28.2 把 src/index.ts 打成 dist/index.js，构建结果要提交
npm run check:dist   # 重新构建到临时文件，与 dist/index.js 不一致即失败
npm test             # vitest，借用本机的开源仓 checkout
```

`npm test` 以本目录为根，运行 `$AGNES_HARNESS/node_modules/.bin/vitest`（默认 `~/agnes-harness`，需先在那里装好依赖）；`vitest.config.mjs` 从该 checkout 解析 `@agnes/*` 工作区包及其依赖，这里不发布也不安装它们。`scripts/` 里的验收和浏览器取证脚本同样依赖该 checkout（在其根目录运行，使用独立 AGH home 和明确的模型费用上限）。包不内置账号或密钥。EU GMP Annex 1、Annex 11、21 CFR Part 11、ICH Q9/Q10 与 ALCOA+ 仅作术语参考，不代表合规认证。
